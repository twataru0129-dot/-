- 107件の名称を全件プログラムで突き合わせ、**完全一致する重複名称は0件**でした。既存12称号の名称(国旗ビギナー等)が#1〜100に誤って再利用されていないことも確認済みです。
- 国名48件(#71〜89, #91〜100, #75)を`js/countries.js`で再照合し、**存在しない国名・IDはありませんでした**(前回報告どおり)。新たに追加された#67「世界の反対側」(日本・ブラジル)も`jp`/`br`として存在を確認済みです。

- 数値条件(○問中○問以上正解等)はすべて「正解数 ≤ 総問題数」の範囲内で、**数学的に不可能な条件はありませんでした**。

- **難易度カーブの非単調性(軽微、参考情報)**: #11〜14(50/100/198問コースの正解率閾値)が 80%→90%→75.8%→95.9% と単調に上がらない構成になっています(#13が198問で150問=約75.8%と、#12の100問で90問=90%より緩い基準)。実装上の問題ではありませんが、意図通りか念のため触れておきます。

## 4. 実装前にユーザー判断が必要な事項(番号別・選択肢付き)

以下は、既に確定している仕様を変更する提案ではなく、**統合仕様書の文言だけでは実装方法が一意に決まらない箇所**です。

### #1〜19・#17(横断的課題): モード別デュアル状態の実装方法
24件が「1トロフィー番号=国旗/首都で独立した2状態」という設計です。
- **選択肢A**: 1つの`trophy_id`の`earned`データを`{flag: {earnedAt}, capital: {earnedAt}}`のような複合オブジェクトにする(番号は1つのまま、内部で2状態管理)
- **選択肢B**: 内部的に`trophy_17_flag`/`trophy_17_capital`のような補助idで2件管理し、画面表示でだけ1つの番号として束ねる
- **選択肢C**: 今回の24件専用に`TrophyModule`へ「モード別トロフィー」という新しいカテゴリーのAPIを別途用意する

### #51: 「挑戦回数」の定義
統合仕様書は「要照合」としていますが、**これはコード調査で解決済みです**。`Storage.incrementAttempts(mode)`は`js/app.js:544`の`finishQuiz()`内でのみ呼ばれるため、**「挑戦回数」は常に「完了回数」です**(途中終了はカウントされません)。この点は再確認不要と判断しましたが、念のため記載します。

### #52: 国旗198問+首都10問という非対称な条件
- **選択肢A**: 記載どおり「国旗198問満点+首都10問満点」(非対称のまま)
- **選択肢B**: 本来は対称な組合せ(例: 両方198問、または両方10問)の誤記
いずれかをご確認ください。

### #53: 対象モード
- **選択肢A**: 国旗・首都それぞれ独立した2つの達成状態(#17と同系統)
- **選択肢B**: どちらか一方で達成すれば共通で1回だけ獲得

### #54: 「100回完了後」の判定基準
- **選択肢A**: 現在の合計完了回数が100以上、かつ(今回の完了または過去のいずれかの完了が)満点であれば獲得(= 100回目より前に満点を達成していた場合も対象に含む、実装が簡単)
- **選択肢B**: 合計完了回数が100に到達した**後に行われたプレイ**で初めて満点を達成した場合のみ獲得(= 100回目以降の満点のみが対象。達成した順番の記録が別途必要)

### #58の新規カウンタ
- **選択肢A**: トロフィー専用の新規キー(`js/trophy.js`側、`js/storage.js`は変更しない)にモード別カウンタを追加
- **選択肢B**: `js/storage.js`の`BEST_RECORDS`等を拡張してカウンタを追加
(前回提案どおりAを推奨しますが、ご確認をお願いします)

### #60: 対象モード・回数の合算方法
- **選択肢A**: 国旗・首都で別々に3回ずつ数える(モード別デュアル状態)
- **選択肢B**: 国旗・首都合算で3回に到達すれば共通で1回獲得

### #62「虹の架け橋」: 対象モード
- **選択肢A**: 国旗・首都共通(どちらのプレイでも可)
- **選択肢B**: 国旗限定または首都限定

### #64「真夜中の探検家」: 開始/終了時刻、対象モード
- **選択肢A**: #70と同様に「プレイ開始時刻」が0:00〜2:59であることを判定(新しい開始時フックが必要)
- **選択肢B**: プレイ終了時点の時刻で判定する簡易版(既存の結果確定フックのみで実装可能だが、「開始時刻」という文言とは厳密には一致しない)
- 対象モード(共通/国旗限定/首都限定)も併せてご確認ください

### #66「リベンジ成功！」: 「直前の記録」の定義
- **選択肢A**: 「直前の記録」=このプレイの**直前にプレイしたときの正解数**(時系列で1つ前、ベスト記録ではない)。この場合、コースごとに「前回の正解数」を保存する新しいデータが必要
- **選択肢B**: 「直前の記録」=このプレイを**保存する前の時点での最高記録**(`updateBestRecord`が上書きする前の値をそのまま使う)。この場合、新規の永続データは不要(同じ`finishQuiz()`内で「更新前の値を読んでから更新する」だけで実現可能)
- 対象モード(共通/モード別)も併せてご確認ください

### #68「逆転の天才」: モードをまたぐ設計の意図確認
国旗で間違えた国を首都で正解、という**モードをまたぐ**条件です。共通ルールの「異なるプレイやモードを合算しない」はペア系トロフィー(#71〜100)の文脈で述べられたものと理解していますが、#68は設計として意図的にモードをまたぐ仕様に見えます。
- **選択肢A**: 記載どおり、モードをまたぐ仕様として確定(共通ルールの「モード合算禁止」はペア系トロフィーのみに適用され、#68には適用されない)
- **選択肢B**: 誤記で、実際は同一モード内での条件(例: 国旗で間違えた国を**別の国旗プレイ**で正解=#63と統合すべき)

### #20〜29全般: 計測の実装範囲
#69用に提案した「最終1問だけ一時変数で保持」という最小実装では対応できません。
- **選択肢A**: 国旗/首都クイズの`handleAnswer()`に、各問題の回答時間を**プレイ中だけ**配列やカウンタで保持する仕組みを新規に追加(永続化は「条件を満たした瞬間のトロフィー獲得」のみ)
- **選択肢B**: #20〜29は今回の実装範囲から外し、後続の段階に回す

### #30〜39全般: 新規データの規模感の確認
flag/capital向けに「国・地域ごとの生涯正解履歴」(#30〜38は真偽値、#39はさらに回数)を新設する必要があり、データ量・実装範囲ともに今回確認した他の項目より大きくなります。
- **選択肢A**: 今回のスコープに含めて新規データを設計する
- **選択肢B**: 後続の段階に回す

## 5. 既存12称号・他のゲーム機能への影響

- 今回の統合仕様書で参照している既存データ関数(`Storage.hasTitle`/`getEarnedTitles`/`getAttempts`/`getBestRecords`)は、**すべて読み取り専用の呼び出しのみ**で、既存12称号のデータ形式・保存キー・判定ロジックを一切変更しません。
- #101〜112は新規に`wfq_v1_trophy_earned`へ書き込まない「参照型」として設計する方針を維持しており、既存称号の獲得履歴の二重管理・初期化は発生しません。
- 新規に必要となるデータ(3-C・3-D章)は、いずれも**新しいキーを追加する形**で設計可能であり、既存のキー(`wfq_v1_earned_titles`・`wfq_v1_capital_earned_titles`・`wfq_v1_attempts_count`等)の形式変更は不要と判断しています。
- 今回確認した107件はすべて**国旗クイズ・首都クイズのみを対象**としており、世界地図・世界図鑑・「世界の国どこかな？」・PROモード・findcountryのランキング/コレクション/PRO解放には一切関与しません(仕様書中にもfindcountryへの言及はありませんでした)。
- `Storage.resetAll()`への新規キーの組み込み方針は、前回報告のとおり未決定のまま残っています。
