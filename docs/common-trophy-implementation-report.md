## 5. 追加した保存データの内容

既存の`js/storage.js`のSTORAGE_PREFIX方式に従い、`wfq_v1_common_progress`という
1つのキーに、以下の内容をバージョン付き(version: 1)でまとめて保存している
(スクリーンごとの個別保存は行わず、一元管理している)。

- `playCompletedCount` { flag, capital, findcountry }: モード別プレイ完了回数
- `correctCount` / `wrongCount` { flag, capital, findcountry }: モード別累計正解・誤答数
  (誤答はパス・時間切れを含めず、回答確定時点で記録)
- `perfect30Achieved` { flag, capital, findcountry }: 30問パーフェクトクリア済みか
- `clear198Achieved` { flag, capital }: 198問クリア済みか
- `clearAdvanced30Achieved`: どこかな？上級30問クリア済みか
- `playedDates`: プレイ完了した日付(YYYY-MM-DD)の集合(累計プレイ日数用)
- `lastPlayedDate` / `currentStreakDays` / `maxStreakDays`: 連続プレイ日数
- `dailyClear` { date, flag, capital, findcountry }: 当日の3クイズクリア状況(三位一体用)
- `usedFlag` / `usedCapital` / `usedFindCountry` / `usedMap` / `usedEncyclopedia`: 四つの扉用の利用履歴

既存の保存キー・既存ユーザーのトロフィー獲得記録・獲得日時は一切変更・削除して
いない。このキーは将来のプロフィール機能実装時に、プロフィールごとに分割しや
すい構造(フラットなオブジェクト1つ)にしてある(プロフィール機能自体は今回実装
していない)。

## 6. 既存データからの遡及反映の状況

アプリ起動時(`initApp()`)に`evaluateCommonTrophiesCatchUp()`を1回呼び、以下の
利用履歴のみ、既存データから確実に導出できる範囲で遡及的に反映した。

- `usedFlag` / `usedCapital`: 既存の挑戦回数(`Storage.getAttempts(mode)`)が1回以上あれば true
- `usedFindCountry`: 既存のfindcountry系トロフィーが1件以上獲得済みであれば true
- `usedEncyclopedia`: 既存の図鑑閲覧記録が1件以上あれば true

**遡及反映できなかった項目**(推測による補完は行っていない):
- `usedMap`(世界地図の利用履歴): 既存データに利用有無を一意に判別できる記録がないため未反映
- 累計プレイ完了回数・累計正解数・累計誤答数: 今回の更新以前はこれらを保存して
  いなかったため、履歴データが存在せず、0から記録を開始する
- 連続プレイ日数・累計プレイ日数: 同上の理由で0から記録を開始する

これらは起動直後に不利な扱い(いきなり未達成)になるだけで、既存の獲得済み
トロフィーを取り消すものではない。起動時の遡及評価は、新規に達成条件を満たす
トロフィーがあれば既存の通知キューでまとめて表示し、再起動のたびに重複して
付与されることはない(`awardIfNew()`の既存の重複防止機構をそのまま利用)。

## 9. 循環参照・未到達トロフィーの有無

- 依存関係は一方向(個々の獲得→累計系/完全制覇系→90%/95%→世界の真理)のみで、
  相互に前提とする関係(トロフィーAの獲得にトロフィーBが必要で、Bの獲得にAが
  必要、のような構造)は存在しない。
- `evaluateCommonTrophiesChain()`は「新規獲得が発生した限り再評価を繰り返す」
  方式のため、1回の達成で複数の共通トロフィーが連鎖的に解放される場合も正しく
  処理される。反復回数には`COMMON_TROPHY_NUMBERS.length + 5`(36回)の安全上限を
  設け、上限に達した場合のみconsole.warnでログを残す(8節の全制覇シミュレーション
  では31件すべてが数回以内の反復で解放され、上限には到達していない)。
- ミシックハンター(#402、累計420個)は、8節の結果が示すとおり実際に到達可能
  (世界の真理を先に獲得する必要はない)。
- 90%(#423)・95%(#424)も、世界の真理(#425)を獲得する前の時点で到達可能である
  ことを、`tests/trophy_common_logic.test.js`の閾値境界テストで確認している。

## 13. 未検証・今後の確認事項

### 既存のテスト不安定要因(今回の変更が原因ではないことを確認済み)

- `playwright_afghanistan_wakhan_gap_fix.test.js`の「修正対象領域付近をタップ
  するとアフガニスタンとして判定される」が失敗する。本番コード変更前の
  `origin/main`(PR #87マージ直後のコミット)に対して同じテストを実行しても
  同一の箇所が同一の理由で失敗することを確認済みで、今回の共通トロフィー実装
  とは無関係な既存の問題である。
- `playwright_findcountry_hidden61_end_of_play_notify.test.js`・
  `playwright_findcountry_mistake_events.test.js`は、全27件のPlaywright
  テストを連続実行した場合にのみタイムアウトするが、単体で実行すると(それぞれ
  41件・16件)すべて成功する。ブラウザを連続して多数起動するこのサンドボックス
  環境固有のリソース制約によるものであり、今回の変更による新規の不具合では
  ない。
- `playwright_findcountry_nomiss_record_logic.test.js`・
  `playwright_map_uk_constituents.test.js`・`playwright_map_uk_labels_visibility.test.js`
  は、単体実行でもタイムアウトする(ブラウザプロセスが途中で終了する)。これも
  `origin/main`(今回の変更前のコード)に対して同じテストを単体実行した場合に
  同一の症状で失敗することを確認済みであり、今回の共通トロフィー実装による
  新規の不具合ではない、既存の環境依存の問題である。

- 累計プレイ完了回数1,000回・累計正解100,000問・連続プレイ日数30日等は、実機の
  通常プレイでは短時間に到達できないため、開発者向けテスト環境
  (`dev/common-trophy-lab.html`)上での検証に限定している。実機の通常プレイで
  これらの閾値そのものを数日〜数か月かけて再確認することは、本報告書の範囲外
  とする。
- 実機(iPhone/iPad/PC)での#425専用演出(星空アニメーション・reduced-motion
  対応)の目視確認は、開発者向けテスト環境の「専用演出をプレビュー」ボタンで
  行うことを前提としている。
- 性能面: `evaluateQuizFinish`/`evaluateFindCountryResult`は、共通トロフィーの
  連鎖判定(`evaluateCommonTrophiesChain`)を追加で実行するようになったため、
  1回あたりの処理コストが増加している(Node環境での計測値: 約145ms/回。既存の
  `getEarned()`が呼ばれるたびに保存データの再読込+420件の全トロフィー走査を
  行う既存のアーキテクチャに起因するコストが、連鎖判定の反復によって積み重な
  ったもの)。findcountry内のプレイ中の高頻度呼び出し(`onlyStage:"hidden61"`)
  では連鎖判定をスキップする対策を行ったが、クイズ・どこかな？の結果確定時の
  呼び出し自体のコストは変化していない。実機での触感上の遅延は確認できていない
  (フレーム単位の判定ではなく、プレイ完了・正解確定等のイベント単位でのみ実行
  されるため)が、将来的に`getEarned()`のキャッシュ化等の最適化を検討する余地が
  ある。

## 14. 将来のプロフィール機能実装時の留意事項

- `wfq_v1_common_progress`はフラットな1オブジェクトであるため、プロフィール
  ごとに分割する際は、キー名にプロフィールIDを付加する(例:
  `wfq_v1_profile_<id>_common_progress`)等の対応が必要になる。
- 利用履歴(`usedFlag`等)・連続日数・累計正解数等はいずれも「アプリ全体」で
  1人分の記録として設計しているため、複数プロフィールを扱う場合は、プロフィール
  切り替え時に読み込むストレージキー自体を切り替える設計が妥当である。
- 今回の実装では、プロフィール機能そのもの(複数プロフィールの作成・切り替え・
  共有ストレージの分離)は実装していない。
