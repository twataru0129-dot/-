## 1. 既存12称号との互換性・移行性の確認

- 新トロフィーシステム(`wfq_v1_trophy_earned`)は、現時点で**一度も書き込まれていません**(`js/trophy.js`の107スロットは全てnull/未確定のまま)。したがって**移行すべき既存データは存在しません**(ゼロから開始)。
- #1〜19・#41〜49・#51・#52・#54・#58〜60・#101〜112など、既存の称号・記録データを参照するトロフィーは、いずれも`Storage.getEarnedTitles()`/`Storage.hasTitle()`/`Storage.getAttempts()`/`Storage.getBestRecords()`を**読み取るだけ**で、既存のキー(`wfq_v1_earned_titles`・`wfq_v1_capital_earned_titles`・`wfq_v1_attempts_count`等)やそのデータ形式は一切変更しません。
- #101〜112は新規に`wfq_v1_trophy_earned`へ書き込まない「参照型」として扱うため、既存称号の獲得履歴と新トロフィーの獲得履歴が二重管理になることはありません。
- **結論: 既存12称号・記録データへの移行作業は不要で、互換性リスクはありません**(読み取り専用アクセスのみのため)。

## 9. 特別な隠しトロフィー#142「都の神話」(新規1件・合計137件)

本章は、既存136件(1〜8章)の実装完了後に追加した、特別な隠しトロフィー#142「都の神話」の正式仕様を記録するものです。1〜8章の内容・既存136件の名称/獲得条件/判定ロジック/保存形式/隠しトロフィー仕様は一切変更していません。

### 9.1 正式仕様

| 項目 | 内容 |
|---|---|
| 番号 | No.142 |
| 名称 | 都の神話 |
| 種類 | 特別な隠しトロフィー |
| 獲得条件 | 首都トリビアNo.113〜141の全29種類を獲得 |

正式解説文: 「世界の首都を巡り、29の絆を解き明かした者に贈られる究極の証。その知識は国境を越え、世界中の都をつなぐ。今ここに、都の神話が誕生した。」

獲得時の専用メッセージ: 「首都トリビア完全制覇！」/「その名は――都の神話。」

### 9.2 獲得判定

- `js/trophy.js`に`mode: "legend"`の単一(非デュアル)トロフィーとして追加した(`STAGE_LEGEND_DEFINITIONS`)。
- 判定関数`allCapitalTriviaEarned()`は、首都トリビア(#113〜141)29件それぞれに`isEarned()`を呼ぶだけの純粋関数で、新しい判定の仕組みは追加していない。
- `evaluate()`は`TROPHIES`を番号の昇順(1→142)で走査するため、首都トリビアの29種類目が`awardIfNew()`で保存された直後、同じ`evaluate()`呼び出し内で#142のcheckがその保存結果を読み、その場で獲得登録される。これにより「29種類目を獲得した直後にNo.142も獲得する」という要求を、新しい同期処理を追加せず判定順序だけで満たしている。
- 国旗クイズ・「世界の国どこかな？」では獲得できない(首都トリビア自体が首都クイズ限定のため、前提条件が満たされない)。国旗トリビア(#71〜100)の獲得状況には一切左右されない。#142自身は`CAPITAL_TRIVIA_NUMBERS`(113〜141の配列)に含まれず、判定条件に含めていない。
- 既存の`awardIfNew()`の重複防止により、獲得は1回のみ(2回目以降は再獲得・再登録されない)。

### 9.3 過去データへの対応

- アップデート前に既に首都トリビア29種類すべてを獲得していたプレイヤーに対応するため、`js/trophy.js`のモジュール読み込み時(=アプリ起動時・トロフィー情報の初期化時)に1度だけ`reconcileLegendTrophy()`を実行する。
- 内容は「#142が未獲得かつ29種類すべて獲得済みなら`awardIfNew("trophy_142")`を呼ぶだけ」のシンプルな処理で、`evaluate()`を経由しないため獲得通知・専用演出(9.4節)は一切呼ばれない(アプリ起動のたびに演出が繰り返されることはない)。
- 新規登録される場合の#142の`earnedAt`は、実際にこの処理が実行された時刻になる(過去の日付を推測で補わない)。既存トロフィーの`earnedAt`・保存データの削除/初期化は一切行わない。
- 既に#142を獲得済みの場合は即座に何もせず終了するため、毎回のページ読み込みで実行しても安全(確認のみの軽量な処理)。
