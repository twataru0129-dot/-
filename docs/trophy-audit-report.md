### 1-2. 実施した修正内容

**変更したのは一覧画面の表示用カテゴリー(`category`フィールド)のみ**です。

- `js/trophy.js` の `categoryForNumber()`(2059行目付近)に、`number === MYSTERY_HUNTER_NUMBER` の場合だけ `"puzzle"` を返す分岐を、既存の `SEVEN_WONDERS_ALL_NUMBERS.includes(number)` 判定より前に追加しました。
- `category` フィールドは `js/trophy.js` 内で**一覧画面の表示用ラベルにのみ使われており**(`TROPHIES.filter((t) => t.category === c.id)` のような集計・自己検証アサーション、および `js/app.js` のタブ絞り込み・バッジ表示)、`isAllNormalPuzzlesEarned()`・`isAllSevenWondersEarned()`・`isSevenWondersUnlocked()` などの**獲得判定ロジックのどこからも参照されていない**ことをコード全文の `grep` で確認済みです。そのため、`category`だけを変更しても判定・保存・解放ロジックには一切影響しません。
- **変更していないもの(確認済み):** `id`(`trophy_393`)・`number`(393)・`name`(ミステリーハンター)・`condition`(獲得条件文)・`check`関数(`isAllNormalPuzzlesEarned`)・`hidden`(true)・`stage`(`sevenWondersSpecial`)・`mode`(`sevenWonder`)・`confirmed`(true)。No.394は一切変更していません。
- **循環参照対策:** `isAllNormalPuzzlesEarned()` の判定対象 `PUZZLE_TROPHY_NUMBERS` は `js/puzzle-questions.js` の126問の `trophyNumber` から機械的に作られる固定配列であり、`category` フィールドを一切参照しないため、No.393のカテゴリーを変更しても「謎解き全問獲得」の判定対象に自分自身(#393)が混入することはありません(`isAllNormalPuzzlesEarned()` 関数の実装自体が `category` を見ていないため、構造上混入し得ません)。

#### 発見した「表示だけの変更」では済まない依存箇所と、その対応

調査の過程で、`category` の値をそのまま一覧画面の描画分岐・カテゴリーバッジ文言・既存テストのフィルター条件として使っている箇所が複数あり、**単純に `category` の値だけを書き換えると表示が壊れる**ことが分かりました。「原則として表示上のカテゴリー配置のみを変更する」というご指示に従い、以下のとおり**表示用カテゴリーと内部判定用の分類を区別する最小限の対応**を行いました。

1. **カード描画の分岐(`js/app.js` `renderTrophyGrid()`)**: 従来は `def.category === "sevenWonders"` かどうかで、ミステリーハンター・全知全能の神専用の「未発見時は？？？？？？で完全に伏せる」特別カード(`buildSevenWonderSpecialCard`)に振り分けていました。`category` を `"puzzle"` に変えると、この振り分けより先に `def.category === "puzzle"` の分岐(謎解き専用カード、`buildPuzzleTrophyCardElement`。未獲得でも問題文を常に表示し「この謎に挑む」ボタンを出す仕様)に落ちてしまい、**未発見時の情報開示ルールが変わってしまう**(かつ `puzzleQuestionId` が `null` のため、存在しない問題への「挑む」ボタンが生成されて壊れる)という問題がありました。
   - **対応:** 振り分けの条件を `def.category` ではなく、カテゴリー変更の影響を受けない既存の内部分類 `def.stage === "sevenWondersSpecial"` に変更しました。この`stage`値は元々 `evaluate()` 内で #393・#394 だけを絞り込むために使われている既存の内部マーカーで、今回の変更では一切書き換えていません。これにより、No.393は一覧のタブ分類こそ「謎解きトロフィー」になりますが、カードの見た目・未発見時のマスキング・獲得演出は従来の世界7不思議専用デザインのまま維持されます。
2. **カテゴリーバッジの表示文言(`js/app.js` `buildSevenWonderSpecialCard()`)**: 従来はカード上部のバッジ文言が `"世界7不思議"` の固定文字列でした(`def.category` を参照していなかった)。これをそのままにすると、タブで「謎解きトロフィー」に分類されているにもかかわらずカード自体には「世界7不思議」と表示される不整合が生じます。
   - **対応:** 固定文字列を、`TROPHY_CATEGORY_LABELS[def.category]`(実際のカテゴリーに対応するラベル)を参照する形に変更しました。これにより、No.393は「謎解きトロフィー」、No.394は従来どおり「世界7不思議」と、バッジ表示とタブ絞り込み結果が一致します。
3. **自己検証アサーション(`js/trophy.js` 内の `validateTrophyDefinitions()`)**: `puzzleカテゴリの件数` `sevenWondersカテゴリの件数` を固定式で検証していたため、件数の移動(126→127件・9→8件)に合わせて期待値を更新し、あわせて「No.393のカテゴリーがpuzzleになっていること」「No.394のカテゴリーがsevenWondersのまま保たれていること」を明示的に確認するアサーションを追加しました。
4. **既存テストの潜在的な不具合(今回の変更で表面化):** `tests/playwright_seven_wonders.test.js`(169行目)と `dev/seven-wonders-lab.js`(44行目、開発者専用テストラボの「通常126問をすべて正解にする」ボタンの実装)が、いずれも `TrophyModule.getAllDefinitions().filter((d) => d.category === "puzzle")` で「実際に挑戦できる通常謎解き126問」を取得していました。No.393のカテゴリーが`"puzzle"`になったことで、この絞り込み結果に`puzzleQuestionId: null`のNo.393自身が混入するようになり、特に `playwright_seven_wonders.test.js` では「番号が最大の謎を最後に解く」という処理が、実在しない問題(No.393、`puzzleQuestionId: null`)を参照してクラッシュする状態になっていました(実際に確認済み。下記テスト結果の章を参照)。これは今回の表示カテゴリー変更が直接の原因であるため、Work Aの範囲内の必要な追随修正として、両方の絞り込み条件に `&& d.puzzleQuestionId` を追加し、「実際に挑戦できる謎(問題を持つもの)」だけを対象にするよう修正しました。これ以外の既存コード・テストは変更していません。

1. 共通トロフィー31種類を実装する前に、各トロフィーの「対象ID集合」をコードレベルで明文化し、既存の部分一致トロフィー(No.142・158・262・393・394)との重複範囲を明確にすること。
2. 最終制覇系トロフィー(90%/95%/100%)の分母算出関数を、共通トロフィー追加後の最終的なID総数から動的に計算する形で設計すること(ハードコード禁止)。
3. 累計がんばり系(3-3節)は、新規ストレージの設計(特に日付・連続日数の扱い)を別途詳細に検討すること。遡及反映が不可能である旨を実装前に明示すること。

5. 共通トロフィー同士の連鎖判定(1件獲得が他の共通トロフィーの成立に影響する)と、二重付与・無限ループ防止の仕組みを設計すること。
