# trophy-image-pipeline

「世界の国旗クイズ」のトロフィー固有画像を量産するための、本体アプリとは
**完全に独立した**画像加工支援ツール。本体アプリのコード・依存関係・保存
データには一切触れない。ChatGPT等で作った複数トロフィーの画像シート
(例: 3x3=9枚分を1枚にまとめた画像)を入力し、

1. シート内の各トロフィー装飾の実際の配置・境界を検出(単純な均等分割はしない)
2. 背景の透明化(装飾内部の暗い部分は消さない)
3. 円形トリミング時に装飾の先端が欠けないよう余白を付けた正方形化
4. original(最大解像度) / 512 / 256 / 128px の透明背景WebPを書き出し
5. 目視確認用のプレビューモンタージュ画像と品質レポート(JSON)を生成

まで自動で行う。既存のトロフィー一覧UIへの組み込みは行わない(別タスク)。

## 使い方

```bash
cd tools/trophy-image-pipeline
npm install
npm run process -- config/sheets/sample-flag-trivia-9.json
# または: node bin/process-sheet.js config/sheets/sample-flag-trivia-9.json
# 引数省略時は config/sheets/sample-flag-trivia-9.json が使われる
```

実行結果は `output/` 以下に出力される。

```
output/
  original/trophy_71.webp   ... 検出したbboxをそのまま正方形化、可逆WebP
  512/trophy_71.webp        ... 512x512、品質優先の非可逆WebP
  256/trophy_71.webp
  128/trophy_71.webp
  preview/montage.png       ... 全セルの目視確認用プレビュー画像
  quality-report.json       ... 品質確認結果(下記参照)
```

## 新しいシートを処理する(今後の量産向け)

1. `input/` に画像シートを置く(例: `input/my-sheet.png`)。
2. `config/sheets/` に設定JSONを作る。`rows`/`cols` はシートの行数・列数、
   `cells` は **読み順(左→右・上→下)** に並べた各セルの情報。
   `key` が最終的なファイル名(`<key>.webp`)になる。

```json
{
  "sheet": "input/my-sheet.png",
  "rows": 2,
  "cols": 2,
  "cells": [
    { "number": 1, "key": "trophy_1_flag", "name": "〇〇(国旗版)" },
    { "number": 1, "key": "trophy_1_capital", "name": "〇〇(首都版)" },
    { "number": 2, "key": "trophy_2", "name": "△△" },
    { "number": 3, "key": "trophy_3", "name": "□□" }
  ]
}
```

   - 1x1(individual = 1枚だけの画像)も `rows:1, cols:1, cells:[{...1件...}]` で
     そのまま処理できる。
   - 国旗版/首都版のように**同じ表示番号を2つの画像制作単位に分ける**場合は、
     `key` を `trophy_<番号>_flag` / `trophy_<番号>_capital` のように
     分けるだけでよい(トロフィー画像制作事前調査で定義した「画像制作専用
     キー」の考え方をそのまま使える)。ファイル名はすべて`key`から決まる
     ため、コード変更は不要。
3. `node bin/process-sheet.js config/sheets/my-sheet.json` を実行する。
4. 検出個数が `rows*cols` と一致しない場合は、**加工を行わず**
   `output/quality-report.json` に理由を書き出してエラー終了する
   (`problems` を参照)。`darkThreshold` 等を調整するか、シートを
   再生成する。

## 透過PNGシート(アルファチャンネルあり)を扱う場合

ChatGPT等が直接透過PNG(アルファチャンネル付き)でシートを書き出した
場合、カットアウト境界に「ほぼ透明だがRGBだけ明るい色が残っている」
アンプリマルチプライド由来のノイズピクセルが点在することがある。
これをRGB明度だけで判定すると、本来透明であるべきこのノイズが前景
(=装飾の一部)として誤認識され、枠の外周にジャギーなノイズが残って
しまう。

`config/defaults.json` の `alphaBackgroundThreshold`(既定値16)は、
シートが4チャンネル(RGBA)の場合のみ有効で、ネイティブのアルファが
この値未満のピクセルをRGBが何であれ強制的に背景候補として扱う。
アルファチャンネルを持たない(3チャンネル)シートには一切影響しない
ため、既存のシートの出力結果は変わらない。

## 処理アルゴリズムの要点

- **単純な均等グリッド分割はしない。** シート全体に対して「外周から
  たどれる暗いピクセルの連なり=背景」をフラッドフィルで確定し、
  残りを連結成分としてラベリングすることで、各トロフィー装飾の実際の
  配置・境界(バウンディングボックス)を検出する(`lib/foreground-mask.js`)。
  これにより装飾内部の暗い部分(夜空・影など)は誤って透明化されない。
- セルの検出数が列数とだけ一致する(=列は分離できているが、列の中で
  複数行の装飾が接触して1つの塊に融合している)場合は、行境界の
  おおよその位置の近傍で実際に断面が最も細い「くびれ」を自動検出し、
  そこだけをピンポイントで切断する(`lib/split-sheet.js` の
  `analyzeSheetWithAutoSeamCuts`)。これも固定位置での機械的な分割では
  なく、実際のピクセル配置から見つけた最も侵襲の少ない切断点を使う。
- 透明化は、成分ラベルと一致するピクセルだけを不透明として残す方式
  (`lib/process-cell.js`)。そのため、たとえ正方形化のために周囲へ
  余白を広げて切り出しても、隣接する別トロフィーの混入(ブリード)は
  原理的に発生しない。
- 円形表示(`border-radius:50%`)で装飾の先端が欠けないよう、タイトな
  バウンディングボックスに対して余白(`circleSafetyMargin`、既定10%)を
  付けた正方形キャンバスに中央配置する。**この余白が実際に十分かどうかは
  見積もりではなく、書き出した画像の不透明ピクセルが内接円の外側に
  実在しないかを1px単位で直接検査して確認する**
  (`lib/process-cell.js` の `checkCircleSafety`)。

## 品質レポート(`output/quality-report.json`)の読み方

- `problems`: 加工を中断した致命的な問題(空なら加工は正常に完了)。
- `warnings`: 加工は完了したが確認してほしい事項
  (アップスケール発生、目標ファイルサイズ超過、円形クロップでの
  はみ出し等)。
- `seamCutsApplied`: 自動くびれ検出で実際に切断した箇所の一覧
  (どの列の、どのY座標を、なぜ切ったか)。
- `cells[].circleSafety`: 円形表示での実測チェック結果。
- `sourceResolutionNote`: シートのネイティブ解像度に対して512px出力が
  どの程度アップスケールになっているかの要約。

## 修正履歴: 一部画像が斜めに大きく欠けていた不具合(修正済み)

試験加工の初回レビューで、trophy_71/75/87/88/100の5枚でトロフィー本体が
斜めに大きく欠ける不具合が発覚した。原因は`lib/process-cell.js`の
`buildSmoothedAlpha`(エッジのジャギーを滑らかにするためのぼかし処理)に
あった。sharpの`.blur()`は単一チャンネル(グレースケール)の生ピクセルを
渡しても、内部的にsRGB(3チャンネル)へ色空間変換してから処理すること
があり、`.toColourspace("b-w")`を挟まずに`.raw().toBuffer()`すると
出力が3チャンネル(データ量3倍)になる。これを1チャンネルとして読み取って
いたため、1ピクセルごとに読み取り位置がずれていき、結果としてアルファ値
が斜めに大きくずれた縞模様の壊れたマスクになっていた。

前景検出(`lib/foreground-mask.js`)・連結成分ラベリング・自動くびれ検出
自体は検証の結果まったく問題がなく、外周フレームを含むトロフィー本体は
常に1つの完全な塊として正しく検出できていた。欠けていたのは、その後の
ぼかし処理だけが原因だった。

修正: `.blur()`の後に`.toColourspace("b-w")`を挟んでグレースケールに
戻し、出力が本当に1チャンネル・期待サイズであることをアサーションで
検証するようにした。修正後、9枚すべてで本体の欠け・背景の誤残りがない
ことを確認済み(下記「再テスト結果」参照)。

## 既知の制約・次回シート生成への改善条件(今回の試験加工で判明)

1. **隣接する装飾が接触しているシートでは、接触点のごく一部が
   トリミングされる。** 今回の試験シートでは、各トロフィーの円形
   フレーム上下にある菱形の飾りが、上下に隣接するトロフィーの
   飾りと数px〜十数px分だけピクセル的に接触していた。自動くびれ
   検出で接触点を切断することで9枚とも正しく分離できたが、
   その切断幅ぶんだけ菱形飾りの先端がわずかに平らになる
   (イラスト本体への影響はない)。
   → **次回のシート生成では、トロフィー装飾同士の間に
   はっきりとした背景の隙間(目安20px以上)を空けるようプロンプトで
   指定することを推奨する。** 隙間が十分あれば、くびれ検出なしで
   最初から正しく分離でき、装飾も一切トリミングされない。
2. **512px出力は軽度のアップスケールになる。** 今回のシート
   (1536x1024px, 3x3)から検出した正方形キャンバスは平均449px角
   であり、512px出力はこれより大きいためアップスケールが発生する
   (詳細は`sourceResolutionNote`)。
   → 次回は1セルあたりネイティブ解像度が512px角以上になるよう、
   より高解像度のシート(例: 3x3なら2048x2048px以上)を生成する
   ことを推奨する。
3. **512pxでの目標ファイルサイズ(50KB)を、イラストの情報量が多い
   トロフィー(羽毛・複雑な地形など)では超過する場合がある。**
   画質を優先しているため(`config/defaults.json`の`webp.quality`等)、
   サイズ超過は意図的な許容範囲としている。より厳密にサイズを
   詰める場合は`config/defaults.json`の`webp.quality`/`alphaQuality`
   を下げて再実行できるが、画質とのトレードオフになる。
4. **No.87(国旗の動物園)の鳥の種類、No.88(国旗の中の地図)の地図の
   形状の正確性は、今回のツール検証の範囲外。** 今回はあくまで
   画像加工パイプラインの動作検証が目的であり、イラスト内容そのものの
   修正・評価は行っていない。本採用前に別途確認が必要。

## 今後の量産スケーリングに向けて

- 新しいシート1枚ごとに、`config/sheets/*.json` を1つ追加して
  `node bin/process-sheet.js config/sheets/<name>.json` を実行すれば
  同じ処理を繰り返せる。シートのレイアウト(行数・列数・読み順)は
  設定ファイルだけで指定でき、コード変更は不要。
- 将来的に「共通の縁取りフレーム + 中央イラストのみを差し替える」
  合成方式に移行する場合は、`lib/process-cell.js`の
  `extractComponentSquare`が返す「透明背景・中央配置済みの正方形
  イラスト」を、別途用意する共通フレームPNGの上に`sharp().composite()`
  で重ねる処理を追加するだけでよい構造になっている
  (フレームとイラストの分離はまだ実装していないが、本モジュールの
  出力はその合成の入力としてそのまま使える形)。

## ディレクトリ構成

```
tools/trophy-image-pipeline/
  bin/process-sheet.js      CLIエントリーポイント
  lib/
    sheet-io.js              画像読み込み(sharp経由)
    foreground-mask.js       外周フラッドフィル・連結成分ラベリング(低レベル)
    split-sheet.js           グリッド割り当て・自動くびれ検出(高レベル)
    process-cell.js          透明化・正方形化・円形安全性検証・WebP書き出し
    montage.js               プレビューモンタージュ生成
  config/
    defaults.json            既定パラメータ(しきい値・余白・WebP設定等)
    sheets/sample-flag-trivia-9.json  試験シートの設定
  input/                     入力シート画像
  output/                    加工結果(original/128/256/512/preview/quality-report.json)
```
